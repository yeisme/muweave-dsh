# MuWeave DSH 工作台 v8 方案：专业创作工作台

> 状态：方案待定 / 未实施
> 输入：`visual-macos-v6.md`（视觉基线）、`media-workbench`（物理目录模型）、v7 实测界面（10 元件 + 排期 + 工具目录）
> **调研限制**：本轮 `web_search` 因 API 余额不足不可用，`web_fetch` 对 Runway/Figma 等站点被跨域重定向拦截。因此本方案**不含外部产品截图或数据引用**，模式部分来自公开已知的产品形态与本地实测，不编造来源。

## 1. 现在的问题（实测得出，不是猜）

打开 v7 剧场，用户看到的是一张**卡片的瀑布**：10 个元件按 masonry 铺开，每张卡显示标题 + 状态胶囊 + owner + kind。

| 问题 | 证据 |
| --- | --- |
| **没有「我现在该做什么」** | hero 说「Of 10 elements, 1 have a stale baseline and 3 still wait for you」，但**实测可点待办入口为 0**——那 3 件事没有落地通道 |
| **卡片无主次** | 10 张卡视觉重量相同，`Needs Review` 和 `Completed` 一样大 |
| **owner 混流** | eikona 候选、auctra 场次、scaena 分镜、Pi 工件在同一瀑布里，无法按「创作阶段」看 |
| **右栏只有工具目录** | 未选中时是工具目录，选中时是元件详情——两个用途差异极大，却共用一个窄栏 |
| **阶段无用** | 顶部 Visual / Script / Production / Draft / Toolkit 是房间（任务类型），**实测 `hasStageAxis: false`**——没有任何进度轴 |

## 2. 方案核心：三栏改「双轴」

专业创作工具的共同结构不是「更多面板」，而是**两条轴**：

- **纵轴 = 阶段**（灵感 → 剧本 → 视觉 → 分镜 → 声音 → 发布）
- **横轴 = 当前阶段的产物**（变体、版本、审阅状态）

v7 把这两条轴都压进了同一个 masonry。v8 拆开：

```
┌──────────────────────────────────────────────────────────────┐
│ 项目条：雨夜重逢 · 第一集 [准备中] · 10 元件 · 1 待处理     │  ← 保留（v7 已做对）
├────────────┬─────────────────────────────────┬───────────────┤
│ 阶段纵轴   │  阶段工作面（Stage Workbench）  │  检查器        │
│            │                                 │               │
│ ● 灵感  3  │  ┌─────────┬─────────┬───────┐  │  选中：详情   │
│ ● 剧本  2  │  │ 主产物  │ 变体    │ 待办  │  │  未选：工具   │
│ ○ 视觉  4  │  │ (大)    │ (小)    │ 队列  │  │      目录     │
│ ○ 分镜  1  │  └─────────┴─────────┴───────┘  │               │
│ ○ 声音  0  │                                 │               │
│ ○ 发布  —  │  版本条：v1 v2 v3(当前) 对比    │               │
└────────────┴─────────────────────────────────┴───────────────┘
```

### 关键取舍（我的立场）

1. **纵轴用「阶段」不用「owner」**。owner（eikona/scaena）是生产工具，用户思考的单位是「这一步做完了没」。owner 降级为卡片上的小徽章。
2. **每一阶段只给「一个主产物」**。当前阶段最重要的那张卡放大，其余收进变体带。这样「10 张卡一样大」的问题消失。
3. **待办队列常驻**。那只「3 still wait for you」直接变成可点的队列，点一条进详情。
4. **不新增第四个面板**。左纵轴 + 中工作面 + 右检查器，就是专业工具的标准三栏。

## 3. 视觉：从「卡片瀑布」到「工作台」

### 3.1 密度分级

专业工具靠**三级密度**建立秩序，不靠更多颜色：

| 级 | 用途 | 规格 |
| --- | --- | --- |
| L1 主产物 | 当前阶段核心卡 | 大缩略图（16:9 或 4:3）+ 标题 + 一句话状态 |
| L2 变体 | 同产物的可选版本 | 120×90 缩略图网格，选中描蓝边 |
| L3 条目 | 待办队列、审计行 | 单行，等宽数字，发丝线分隔 |

v7 把所有东西都当成 L1，这是「乱」的根源。

### 3.2 阶段纵轴

- 圆点表示阶段状态：实心=已完成，半实心=进行中，空心=未开始
- 右侧数字是「该阶段待处理数」，不是总数（总数没有行动意义）
- 当前阶段整行高亮（`--mw-fill-2` 底 + 左侧 2px 系统蓝）
- 点击切换阶段，**不切房间**——房间是任务类型，阶段是进度

### 3.3 版本条

同一产物有多版本时（候选对比、改写对比），底部一条横向版本带：
`v1 [v2] v3 · 当前基线 v3 · 落后 1 版` + 「并排对比」按钮。
这是 v7 里 `candidate_diff` 卡片想表达但表达不出来的东西。

### 3.4 保持 v6 的约束

- 玻璃只用于浮层（命令面板 / 生成台 / 悬浮助手 / popover）
- 正文、卡片、阶段栏一律不透明
- 只用 `--mw-*` token，rem 单位，无内联样式
- 动效在 `prefers-reduced-motion` 下全停

## 4. 交互：键盘优先

专业工作台的手不离键盘。v8 增加：

| 键 | 行为 |
| --- | --- |
| `j` / `k` | 阶段纵轴上下移动 |
| `Tab` | 在主产物 → 变体 → 待办队列之间跳 |
| `Enter` | 打开选中项详情 |
| `Shift+Enter` | 并排对比当前产物与基线 |
| `g` 然后 `1..6` | 直接跳到第 N 阶段 |
| `⌘K` | 命令面板（已有） |
| `?` | 键位表（已有） |

`⌘` 在 Windows/Linux 显示为 `Ctrl`——v7 遗留问题，这轮一并解决。

## 5. 实施顺序

| 阶段 | 内容 | 判断标准 |
| --- | --- | --- |
| **P0** | 阶段纵轴 + 主产物/变体/待办三级密度 | 进剧场能回答「我在哪一步、下一步做什么」 |
| **P1** | 版本条 + 并排对比 | 有多版本产物时不再靠翻卡片找差异 |
| **P2** | 键盘导航 + `⌘`/`Ctrl` 平台化 | 全程可不用鼠标走完「看阶段 → 开产物 → 对比 → 审批」 |
| **P3** | 删死代码（`DramaSessionView`、`ToolRunCard` 或接线） | 无零引用导出 |

## 6. 不做

- **不做多窗口/拖拽分屏自由布局**：`stage-split` 已有 single/horizontal/vertical 三档，够用；自由分屏的复杂度远超收益。
- **不做深色主题**：v6 已定 macOS 浅色灰阶，双主题会让所有 token 翻倍。
- **不引入图表库**：进度用文字 + 细条，不画饼图。
- **不做外部产品 1:1 复刻**：模式可以借，细节要按内容生产的实际流程定。

## 7. 风险

1. **阶段模型可能与实际工作流不符**。现在的 5 个房间（Overview/Visual/Script/Production/Draft/Toolkit/Schedule）是按任务分的，阶段是另一套划分。如果两者冲突，用户会困惑。
   → 缓解：阶段定义先只覆盖「有产物的」四步（灵感/剧本/视觉/分镜），声音与发布留到有真实数据再接。
2. **左栏加纵轴会挤掉宽度**。1440 宽度下，左 12rem + 右 20rem = 剩约 44rem 给工作面，够用；1024 宽度下要能折叠左栏。
3. **改造面大**。P0 要动 `workspace-shell.tsx` 的 slot 契约和 workbench 的主体布局，属于结构性重构。
