## 1. 现状：机制有，内容空

对比的**框架已经存在**，不用重建：

| 已有 | 位置 |
| --- | --- |
| `WorkspacePresetId = 'balanced' \| 'focus' \| 'compare'` | `workspace-shell.tsx:16` |
| `compareSecondary: ReactNode` 状态 | `workspace-shell.tsx:113` |

| 三档分屏 single / horizontal / vertical | `workspace-shell.tsx` Segmented |

**问题**：`pinBaseline` 推过去的只是一个文字块：

```
标题
owner · kind · sourceRef · vN
sha256:xxxx
```

没有图，没有差异，看不出「这一版和基线到底哪里不同」。所以「对比基线」按钮点了之后，用户得不到对比价值。

## 2. P1 要做的四件事

### 2.1 对比栏里出真图

把推过去的内容从文字块换成 **`StageThumb`（16:9 缩略）+ 元信息**：

```
┌─────────────────────┐
│  [缩略图 16:9]      │   ← 用 media.token 拿图，与 P0 的 L1 同一套
├─────────────────────┤
│ 基线 v2 · eikona    │
│ 沈岚 · 雨夜定妆     │
│ 11-18 16:47         │
└─────────────────────┘
```

左侧是当前主产物，右侧是对比对象。两图同尺寸并排，差异才看得见。

### 2.2 差异摘要（3 条确定性结论，不猜）

对比栏顶部一行断言式摘要，只写能从数据确认的三件事：

| 判断 | 依据 | 文案 |
| --- | --- | --- |
| 版本是否落后 | 两侧 versionLabel 不同 | `基线比当前落后 1 版` |
| 内容是否相同 | digest 相等 | `内容一致（同一 digest）` / `内容不同` |
| 时间差 | updatedAt 差值 | `相隔 6 小时` |

**不写**「更好/更差」——那需要 owner 的评分，现在没有，编造就是假信息。

### 2.3 从变体带直接进对比

L2 变体带的每个候选卡加一个对比角标（悬停出现），点击 = 把该候选设为对比对象并自动进 `compare` 布局。

这样「三个候选里挑一个」的动作变成：点两个 → 看并排 → 采用。不需要先记基线。

### 2.4 退出路径

- `Esc` → 回 `balanced`
- 对比栏右上角 `×` → 清空 `compareSecondary` 回单栏
- 两个都要有，且退出后焦点回到触发按钮（无障碍）

## 3. 视觉规格

| 元素 | 规格 |
| --- | --- |
| 对比栏宽度 | 与主栏等宽（horizontal 分屏下各 50%） |
| 缩略图 | `aspect-ratio: 16/9`，`max-height: 11rem`（与 P0 的 L1 一致） |
| 差异徽章 | `warn` 色（落后）、`ok`（一致）、`neutral`（时间差） |
| 对比栏头 | 一行：`对比` 标签 + 差异摘要 + 关闭按钮 |
| 分隔 | 发丝线 `--mw-line`，不用阴影 |
| 空态 | 未选对比对象时，对比栏显示「选一个候选或基线来并排对比」 |

不动玻璃、不加新色，全部沿用 v6 token。

## 4. 键盘

| 键 | 行为 |
| --- | --- |
| `c` | 对当前 L1 主产物执行「对比基线」（等于点那个按钮） |
| `Esc` | 退出对比 |
| `Tab` | 在左图 / 右图 / 关闭按钮之间移动 |

## 5. 不做

- **不做像素级 diff**：图片 diff 需要图像处理库，收益远小于成本。
- **不做三栏对比**：两个够了，三栏在 1440 下每栏不足 20rem，图看不清。
- **不做「自动选最佳」**：没有评分来源，选不出。
- **不做拖拽交换左右**：位置互换没有实际意义。

## 6. 验收标准

1. 点「对比基线」→ 右侧出现**带缩略图**的对比栏（不是纯文字）
2. 顶部出现差异摘要，且三条判断都能用数据核实
3. 变体带候选点角标 → 直接进对比
4. `Esc` 退出后焦点回到原按钮
5. 未选对比对象时显示空态，不是空白
6. typecheck / test / 静态守卫 / e2e 全绿
